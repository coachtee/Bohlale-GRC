# Mandatory security & privacy rules — release blockers

1. **Consent and authorization:** Public URLs get passive checks only. Active checks require logged-in customer, ownership control (e.g. domain verification or approved repo permissions), explicit target scope, permitted time/testing policy, and unambiguous approval. Avoid third-party probing.
2. **SSRF / network egress:** Reject loopback, RFC1918/private, link-local, multicast, reserved, cloud metadata, DNS rebinding and non-HTTP(S) targets; revalidate on every redirect and connect; enforce outbound allow-lists, strict DNS/IP checks, timeout, max redirect hops and payload sizes. Put scanner workers in locked-down networks.
3. **Code & dependencies:** Use ephemeral, isolated workers with resource limits; read-only least-privilege GitHub auth; no executing untrusted install scripts, CI scripts or repo code in v1. Static scanners must not fetch or execute arbitrary dependencies without strict policy.
4. **Tenant isolation:** Organisation-scoped authz in API, background jobs, blob paths, exports and every query. Test cross-tenant IDs. Report URLs must be unguessable *and* require auth for private results. Public preview tokens expire.
5. **Secrets:** Never print API keys in logs/reports; redact snippets and signed URLs; encrypt tokens at rest; avoid long-lived provider tokens; rotate and revoke; implement least privilege for Bohlale service accounts.
6. **LLM input:** Customer source code and scan evidence is confidential by default. No transmission to DeepSeek, Claude or other external models without explicit authorisation / notice. Redact secrets. Honour provider data-handling terms. Configurable no-AI mode.
7. **Malicious content:** Treat code, URLs, page content, scanner output and MCP/tool manifests as *untrusted data*. Do not let their text modify agent instructions. System-level tool allow-list, typed schemas, bounded loops and sandbox must enforce safety independently of prompts.
8. **AI actions:** Read-only first. Enforce max steps, max input/output tokens, USD/ZAR monetary caps, wall time, concurrency and retry cap per scan, per user, per organisation and globally. Gate patches, PR creation, deployments, account suspension, outbound messages and destructive actions behind human approval.
9. **Data lifecycle:** Minimum-necessary collection; explicit retention periods and customer deletion; encrypted storage and transport; secure file uploads only when isolated malware workflow exists. Maintain data inventory and privacy notice suitable for South African POPIA, including processor and international transfer consideration.
10. **Findings integrity:** Evidence sourced from known tools / reproducible tests. Never invent vulnerabilities, severity, detection engines, proof or verification. Record coverage gaps and engine errors; do not silently label partially scanned target as 'clean'.
11. **Billing and abuse:** Verify payment provider webhook signatures and idempotency; ledger every paid scan; refund/failed-scan workflow; quota limits to prevent free-tier abuse and denial-of-wallet. No hardcoded model prices.
12. **Operational gates:** Secure deployment, dependency audit, TLS, backups/restores, monitoring, incident plan, audit trails, vulnerability disclosure mechanism, rate limits and threat modelling of scanner itself. Do not claim production-ready until independently validated.
13. **Monitoring features later:** Wazuh / file intelligence providers via their permitted licences, customer authorisation and minimal telemetry. VirusTotal Public API **cannot be assumed commercial-use eligible**; do not transmit private material there.

**Failure policy:** If a scanner, provider, webhook, authorization or user quota fails, fail closed and state *incomplete*, not *passed*.
